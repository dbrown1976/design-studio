# Interaction rules

## Actionable status

When a workflow has blockers or follow-up work, prioritise:

1. what requires attention;
2. the action the user can take;
3. the effect of that action.

Administrative metadata is subordinate to actionable state.

## Resolve actions visibly

When an action resolves an issue, update the surrounding workflow state. Remove
or transition the resolved item where appropriate, update counts, and show a
clear success acknowledgement rather than leaving stale error/attention UI.

## Links and actions

Use consistent treatment for equivalent actions. If opening an item in another
product surface is itself the resolution step, encode that behaviour consistently
instead of mixing arbitrary link and button treatments.

## Names and definitions

Prefer one stable name for a view or object. Do not create competing headlines
for the same thing. Distinguish a view's fixed definition from filters the user
can change within that view.
